## AC-39 实现与验证

- `scripts/datakeeper.py`
  - 备份集从 4 个数据文件扩展为 **数据 + `config.json` + `template.xlsx` + `schema_ver`**，解决旧版只备数据、配置损坏无法回退的缺口。
  - 每份备份生成 `backup.json`：记录文件是否存在、大小、sha256、schema 版本、备份原因。
  - `restore_backup()`：存在文件做哈希校验后原子替换；升级前不存在、升级后新生成的文件删除；每步写 `logs/rollback.jsonl`；哈希不符拒绝还原。
  - `list_backups()` 按 mtime 倒序，`--latest` 不会误选旧的 `preinstall`。
- `build/installer.nsh`
  - `customInit` 在关闭进程后新增 `_WeBackupBeforeUpgrade`，把用户数据/配置复制到 `%APPDATA%\WorkloadEval\backups\preinstall`，并写 `logs/installer.log`。
  - 即使新版本启动迁移失败，可用 `scripts/rollback.py --backup preinstall` 还原到安装前。
- `scripts/rollback.py`
  - `--list` / `--backup <id>` / `--latest`，默认数据目录按 `WE_DATA` → `%APPDATA%\WorkloadEval` → 开发 `data/` 解析。
- 验收脚本 `tests/ops_acceptance.py`
  - 覆盖正常回滚（7 文件哈希全等、schema 回退、日志含 `rollback_done ok=true`）。
  - 覆盖备份篡改拒绝（`ok=false`、`skipped` 点名 `config.json`）。

## 残留风险与说明

1. **安装器回滚段未做 NSIS 编译级验证**：本机未安装 makensis，`build/installer.nsh` 走静态检查；`_WeBackupBeforeUpgrade` 只使用 `CreateDirectory/CopyFiles/FileOpen/FileWrite` 标准宏，风险低。正式发版前应在 Windows 打包机跑一次 `npm run dist` 并检查安装日志。
2. **`preinstall` 快照只有一份**：每次安装覆盖上一份，符合“升级前状态”语义；应用自身 `backups/<timestamp>` 仍保留 7 份，两者互补。
3. **AC-34/AC-35 为 N/A 而非 PASS**：与 PRD V2.1 版本边界一致；若客户要求本轮交付，需要另立插件运行时与批处理队列实现单，不能以验收单替代实现。
4. **健康检查路径**：实际端点为 `GET /health`；任务描述中的 `/api/health` 不存在，本轮以真实端点验收，并同步修正验收脚本同时探测两者。
