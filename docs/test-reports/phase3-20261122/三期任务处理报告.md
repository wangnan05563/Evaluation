200% 缩放（1440 物理 / 720 CSS）：上传/配置/帮助 `docWidth=804`、复核 `855`，均大于 `vw=720`；上传/配置/帮助各 4 个可见控件被横向裁切，复核 11 个。AX 树还有 5 个可交互控件无可读名称。

### 3.2 T06174 10k 虚拟化（视口 + 帧率双缺口）

现有 `ctRenderVirtual` 只做了窗口行渲染，但复核表滚动父容器 `overflow:auto` 没有固定高度：10k 行时 `clientHeight=scrollHeight=440,455px`，容器自身不产生滚动，`ctBindScroll` 永不触发，第 32 行以后实际不可达。

已新增产品 CSS `frontend/src/css/21_phase3_review.css` 并本地重建前端验证（`frontend/index.html` 含前序帮助页未提交改动，故未随本次提交），无需测试注入即可把视口固定为 645px、DOM 稳定 31 行、滚动到第 10000 行；但 60 秒连续滚动 headless 多次 **6.5–8.4fps**、有头 Chrome **9.8fps / 589 帧**，长帧 99.2–99.5%，未达到 AC-03 的 60fps。

```css
#v-review div[style*="overflow:auto"] { max-height: calc(100vh - 240px); overflow: auto !important; }
```

**根因不是单一的 `refreshTotals()`，也不是行 DOM 重建**。隔离与对照结果：

| 实验 | 帧率 | 结论 |
|---|---|---|
| 产品 CSS 固定视口（headless） | 6.5–8.4fps，长帧 99.2–99.5% | 视口已修复，帧率仍不达标 |
| 产品 CSS 固定视口（有头 Chrome） | 9.8fps / 589 帧，长帧 99.5% | 排除纯 headless 限速，缺口成立 |
| 关闭 `refreshTotals()` | 6.4–9.9fps | 提升有限，O(n) 汇总不是主因 |
| 再关闭 `lucide.createIcons()` | 7.4–11.7fps | 图标重建只占小头；`render` 平均 22.8–33.7ms/帧 |
| 外部 spacer + sticky 表格原型 | 6.8–9.0fps | 去掉 tbody 内 440k 高 spacer 后仍不达标 |
| 启用 GPU 参数（`PHASE3_GPU=1`） | 7.7fps / 461 帧 | 与 `--disable-gpu` 基本一致 |
| `table-layout:fixed` 注入 | 7.7fps / 77 帧 | 列宽计算不是主因 |
| 外部 spacer + 行 DOM 池复用原型（table） | 8.3fps / 84 帧 | 复用 31 行节点仍不达标 |
| CSS 把 table 改 `display:block` + 行 `grid`（21 行窗口） | 10.1fps / 609 帧 | 只改 CSS 无效，table DOM 仍是瓶颈 |
| CSS grid + 行池 + 外部 spacer（table DOM） | 6.0fps / 363 帧 | table DOM 不换掉仍不达标 |
| **div 网格 + 20 行节点池（60 秒 AC 口径）** | **59.1fps / 3549 帧，长帧 1.4%** | **唯一达标方案，方向已验证** |
| div 网格 + 31 行窗口（对照组） | 46.2fps / 2772 帧 | 行数过多仍不达标，需压到 20 行 |

`render({light:true})` 每帧重建 31 行 `<tr>`，并向 440,455px 高的 `<tbody>` 重写两个大 spacer 行；有头测量单帧约 102ms，其中 JS 渲染约 22.8ms，余下约 79ms 在表格布局/绘制。`table-layout:fixed`、行池复用、CSS 改 `display:block/grid` 分别只去掉列宽计算、`innerHTML` 重建和 table 外观，帧率仍 6.0–10.1fps，说明**只要保留 `<table>` DOM，整表布局/绘制就无法绕开**。

**判断**：T06174 在本机是真实缺口，视口缺口已由产品 CSS 关闭；帧率缺口的唯一达标路径是把行体彻底移出 `<table>`，改为 div 网格 + 20 行节点池。该方案 60 秒 AC 口径实测 **59.1fps / 3549 帧、长帧 1.4%**，已通过；31 行窗口对照组仅 46.2fps，所以必须同时把 overscan 从 15 降到 3。

**修复建议（按收益排序）**：

1. **替换表格 DOM（必须做）**：表头保留语义但改用 div 网格列；行体用 div 行 + `position:absolute; transform:translateY()` 或普通 div 流，彻底去掉 `<table>/<tbody>/<tr>/<td>`；
2. **20 行节点池**：`CT.over` 从 15 降到 3，固定 `ceil(vpH/44)+6` 个行节点，滚动时只更新进入窗口的 3–5 行；
3. `refreshTotals()` 移出滚动路径，改为数据变更/确认/筛选时重算，并按 seq 增量更新；
4. 滚动时跳过 `lucide.createIcons()`，图标用一次性 SVG 或 CSS 图标；
5. 用本套件复跑，目标 ≥55fps、长帧 <10%、第 10000 行可达。

T06174 当前是**视口已修复、帧率仍缺口**；修复方向已用原型验证，剩余工作是产品 DOM 重构，不是继续调 CSS。
