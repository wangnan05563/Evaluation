| 页面 | 阻断项 |
|---|---|
| 上传页 | `label` 2（费率输入 2.57/10.67 无标签）、`select-name` 5（含 `#methodSel`） |
| 复核页 | `aria-allowed-attr` 3（排序表头同时 role=button + aria-sort）、`aria-required-children` 1（div rowgroup 拥有关系）、`color-contrast` 38、`select-name` 83；行复选框已补 `aria-label`，`label` 项由 20 清零 |
| 配置页 | `label` 25、`select-name` 15、`color-contrast` 1 |
| 帮助页 | `color-contrast` 1 |

200% 缩放（1440 物理 / 720 CSS）：上传/配置/帮助 `docWidth=804`、复核 `945`，均大于 `vw=720`；上传/配置/帮助各 4 个可见控件被横向裁切，复核 13 个。AX 树还有 5 个可交互控件无可读名称。div 网格的固定列宽使复核页 200% 横向溢出从 855 增至 945，是 T06173 后续必须处理的回归点。

**建议修复顺序**：先补 `aria-label`/`label` 与 select 名称（结构性、低风险）；再把排序表头改为 `role=columnheader + 内部 button` 或去掉非法 `aria-sort`；随后统一复核表 badge/次级文字对比度；最后补 ≤767px 的宽度约束与 200% 缩放回归。预计 2–3 人日，完成后重跑本套件至 17/17。

### 3.2 T06174 10k 虚拟化（已闭环）

旧实现的滚动容器没有固定高度，10k 行时 `clientHeight=scrollHeight=440,455px`，`ctBindScroll` 永不触发，第 32 行以后不可达。固定视口后暴露出真正的瓶颈：只要保留 `<table>` DOM，整表布局/绘制就把帧率压在 6–10fps；`table-layout:fixed`、复用 `<tr>`、CSS 改 `display:block/grid`、外部 spacer 均无法绕开。

产品最终改动：

1. `frontend/src/index.src.html`：移除 `<table><thead><tbody>`，改为 `.ct-head`（9 列，移出滚动容器）+ `.ct-scroll` + `#tbody.ct-body`；表头保留 `role=columnheader`、排序按钮与 `aria-sort`。
2. `frontend/src/css/21_phase3_review.css`：9 列 grid；视口 `max(300px, calc(100vh - 506px))`，900 高下 394px、9 行，表格下沿止于底部 sticky dockbar 上方，行不再被汇总条遮住；`.ct-rows` 绝对定位 + `will-change/contain`。
3. `frontend/src/js/21_component_table.js`：关键行池（Map seq→slot）只增删进出窗口的行，未变行节点不重建；单容器 `translateY(first*44px)` 位移；缓存滚动容器与视口高，隐藏页首次渲染用 600 兜底，可见后一次 rAF 校正。
4. `frontend/src/js/01_core.js`：div 行渲染；>1000 行启用紧凑只读行（`liteLimit`），滚动 light 路径跳过 `buildTree/refreshTotals/lucide`；复选框事件委托；排序态查询改 `.ct-h`。

实测（60 秒 AC 口径，9 行窗口）：

| 环境 | 帧率 | 长帧 >20ms | 套件 |
|---|---|---|---|
| 有头 Chrome / GPU | **60.0fps / 3598 帧** | **0.1% (5)** | 9/9 |
| 无头 Chrome / GPU | 56.5–58.7fps | 1.5–4.2% | 9/9 |
| 纯 CPU 对照（非验收路径） | 45–52fps | — | 部分失败 |

三组均能滚动到第 10000 行，末窗口包含 `功能项 10000` 且整行在 dockbar 上方可见，`blank=0`，窗口行数恒为 9。

**旧原型 59.1fps 结论作废**：`proto_10k_divgrid.mjs` 把 440k 高 spacer 放在 sticky 行层之前，行层静态位置在文档底部，滚动时行根本不在视口内，浏览器几乎不用绘制。该结果 59.1/59.2fps 但截图空表，不能作为达标证据；本报告与矩阵已改为真实产品实测。

**AC-03 判定**：60Hz 显示器 vsync 上限约 59.94fps，有头实测 3598 帧/60s ≈ 59.97fps，已到满帧；验收阈值 55fps 通过，长帧 0.1% 远低于 10%。若验收要求 120Hz 设备上的 120fps，则需另立口径，不属于本任务 60fps 档。

**待产品确认**：>1000 行时行内编辑控件（类型下拉、确认开关）收起，改为“勾选 + 批量操作”，这是为 10k 性能引入的新交互；上线前需产品明确接受该降级。
