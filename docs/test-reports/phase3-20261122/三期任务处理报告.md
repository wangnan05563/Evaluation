### 2.1 PDF 引擎结论

- Chromium printToPDF：Electron 已内置、零新增运行时；中文字体子集嵌入稳定；页脚页码、书签、水印均通过。
- 目录页码用“两遍渲染 + PyMuPDF 定位章节页”补偿 Chromium 不支持 `target-counter()` 的短板；17/17 页码一致，正式版 3.6s，满足单包 ≤30s。
- WeasyPrint 原生支持 `target-counter()`，但 Windows 需 GTK/Pango，安装包与故障面显著增加；本机未安装（`ModuleNotFoundError`）。**默认不进安装包**。
- 字节级确定性：两次渲染文本哈希一致，字节差异仅 `creationDate/modDate`；若验收要求字节级快照，需渲染后规范化元数据。

## 3. 缺口与处理建议

### 3.1 T06173 WCAG 2.2 AA（P0，未通过）

axe-core 4.10.2 实测 serious/critical 未清零：

| 页面 | 阻断项 |
|---|---|
| 上传页 | `label` 2（费率输入 2.57/10.67 无标签）、`select-name` 5（含 `#methodSel`） |
| 复核页 | `aria-allowed-attr` 3（排序 `th` 同时 role=button + aria-sort）、`color-contrast` 60、`label` 20（行复选框）、`select-name` 83 |
| 配置页 | `label` 25、`select-name` 15、`color-contrast` 1 |
| 帮助页 | `color-contrast` 1 |

200% 缩放（1440 物理 / 720 CSS）：上传/配置/帮助 `docWidth=804`、复核 `855`，均大于 `vw=720`；上传/配置/帮助各 4 个可见控件被横向裁切，复核 11 个。AX 树还有 5 个可交互控件无可读名称。

**建议修复顺序**：先补 `aria-label`/`label` 与 select 名称（结构性、低风险）；再把排序表头改为 `role=columnheader + 内部 button` 或去掉非法 `aria-sort`；随后统一复核表 badge/次级文字对比度；最后补 ≤767px 的宽度约束与 200% 缩放回归。预计 2–3 人日，完成后重跑本套件至 17/17。

### 3.2 T06174 10k 虚拟化（视口 + 帧率双缺口）

现有 `ctRenderVirtual` 只做了窗口行渲染，但复核表滚动父容器 `overflow:auto` 没有固定高度：10k 行时 `clientHeight=scrollHeight=440,455px`，容器自身不产生滚动，`ctBindScroll` 永不触发，第 32 行以后实际不可达。

测试中注入以下 1 条 CSS 后，视口变为 645px、DOM 稳定 31 行、可滚动到第 10000 行；但 60 秒连续滚动仅 **8.1fps / 488 帧，99.4% 帧超过 20ms**，未达到 AC-03 的 60fps。

```css
#v-review div[style*="overflow:auto"] { max-height: calc(100vh - 240px); overflow: auto !important; }
```

**根因不是单一的 `refreshTotals()`**。两层隔离结果：

| 实验 | 帧率 | 结论 |
|---|---|---|
| 仅固定视口 | 8.1fps / 488 帧，长帧 99.4% | 基线不达标 |
| 关闭 `refreshTotals()` | 8.9fps / 89 帧 | 提升有限，O(n) 汇总不是主因 |
| 再关闭 `lucide.createIcons()` | 11.3fps / 113 帧 | 图标重建只占小头；`render` 平均 23.6ms/帧，仍余约 65ms |

`render({light:true})` 每帧重建 31 行 `<tr>`，并向 440,455px 高的 `<tbody>` 重写两个大 spacer 行；表格布局/绘制被整体失效，单帧成本约 89ms，其中 JS 渲染仅 23.7ms。**仅靠 CSS 固定视口 + 去掉汇总无法达标**。

**修复建议（按收益排序）**：

1. 行容器重构：表头与行体拆开，行体改绝对定位（`position:absolute; transform:translateY()`）或 div 网格，spacer 只保留一个总高占位，避免每次重排整张表；
2. `refreshTotals()` 移出滚动路径，改为数据变更/确认/筛选时重算，并按 seq 增量更新；
3. 滚动时跳过 `lucide.createIcons()`，图标用一次性 SVG 或 CSS 图标；
4. 落固定视口 CSS 后，用本套件复跑，目标 ≥55fps、长帧 <10%、第 10000 行可达。

这是 T06174 从“原型”转“产品完成”的三个动作：**固定视口 + 行容器重构 + 汇总/图标去滚动路径**。
