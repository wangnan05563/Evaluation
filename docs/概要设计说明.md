> 状态：现行架构口径（初版 V0.1 于 2026-09 立项，随实现演进；本文件已按当前代码校正）

## 一、定位与范围

面向造价评估人员的**半自动**工作量评估工具：上传需求说明书（docx）→ 引擎按 IFPUG 规则识别候选功能点 → 人工逐条复核 → 生成与企业造价母版完全一致的成品评估表（xlsx）。同时提供 NESMA 快速估算、GB/T 36964 国标造价与 PERT 三点估算。

- **输入**：需求说明书（docx）、人工录入的估算项、配置中心的费率与母版
- **输出**：成品 xlsx（《规模估算》《费用估算》）、PERT 成品表、用户故事（MD/CSV）、导出摘要
- **不做**：全自动无审核出表、报价审批流转、移动端适配、云端同步

**术语**

| 术语 | 含义 |
|---|---|
| 功能点 | IFPUG 五类：ILF / EIF / EI / EO / EQ |
| UFP | 未调整功能点（按复杂度矩阵加权） |
| US | 规模明细：`UFP × 重用系数 × 修改系数` |
| 候选清单 | 引擎识别出的待人工确认功能点集合 |

## 二、总体架构

```
浏览器界面（frontend/index.html 单文件，无框架、无 CDN）
   │  HTTP / JSON（本机 127.0.0.1）
   ▼
本地引擎（scripts/server.py，stdlib http.server）
   ├── 识别：replay_recognize.py（规则表）+ 可选 LLM 增强
   ├── 计算：engine.py（IFPUG 母版口径）/ gb_engine.py（NESMA 与国标造价）
   ├── 出表：generate_xlsx.py（母版保真）/ pert.py（PERT 成品表）
   └── 存储：SQLite（estimation.db / pert.db）+ JSON（规则、费率、配置）
```

**部署形态**

- 开发态：`python scripts/server.py 8020 --serve-frontend`，浏览器访问 `http://127.0.0.1:8020`
- 桌面态：Electron 壳（`dev-shell/`）拉起 PyInstaller 单文件 sidecar，窗口内托管同一前端
- 全程本地运行，不依赖公网；LLM 增强为可选，由使用者自配可访问的 OpenAI 兼容接口

## 四、关键数据模型

**估算历史（`estimation.db`）**

```sql
CREATE TABLE IF NOT EXISTS estimation_history (
  id            TEXT PRIMARY KEY,            -- uuid
  created_at    TEXT NOT NULL,               -- ISO8601 本地时间
  updated_at    TEXT NOT NULL,
  title         TEXT NOT NULL,               -- 需求标题（生成 sid 的基名）
  source_name   TEXT,                        -- 上传文档原始文件名（可空）
  method        TEXT NOT NULL,               -- 估算功能点 | 预估功能点 | NESMA…
  params_json   TEXT NOT NULL,               -- 识别参数快照
  items_json    TEXT NOT NULL,               -- 复核确认后的明细（与 /api/generate 请求体同构）
  summary_json  TEXT,                        -- 服务端返回的 summary
  sid           TEXT,                        -- 成品文件名（data/generated/<sid>）
  version_group TEXT NOT NULL,               -- 版本组键
  version_no    INTEGER NOT NULL DEFAULT 1,  -- 组内递增
  schema_ver    INTEGER NOT NULL DEFAULT 1
);
```

- `items_json` 与 `/api/generate` 请求体字段一致，重开时直接还原为复核态，不做字段翻译
- 重开（不换标题）沿用版本组、`version_no+1`；另存为（换标题）新建组 —— 该键是版本 diff 的基础
- 保留最近 500 条（`WE_HIST_MAX` 可配），写入时惰性清理；历史库不参与任何上传

## 五、计算口径

### 5.1 IFPUG 母版管线（正式造价）

1. 复杂度矩阵：ILF/EIF 用 `RET×DET`；EI/EO/EQ 用 `FTR×DET`
2. 类别默认 UFP：ILF 10 / EIF 7 / EI 4 / EO 5 / EQ 4（预估功能点法：ILF 35 / EIF 15）
3. `US = UFP × 重用系数（高 1/3、中 2/3、低 1）× 修改系数（新增 1、修改 0.8、删除 0.2）`
4. 调整后规模 = 累计规模 × 规模变更因子（早期 1.39 / 中期 1.21 / 晚期 1.10 / 交付后 1.00）
5. 工作量 = 调整后规模 × 生产率（中值 10.67 人时/FP）÷ 8 × 调整因子 0.8（低/中/高 ±20%）
6. 费用 = 工作量 ÷ 22 人/月 × 2.57 万元/人月

**金标准**：用母版既有 45 条明细原样重建，引擎复算 `US 合计 = 105.07`，沿费用链路复现
`127.13 FP → 108.52/135.65/162.78 人天 → 12.68/15.85/19.02 万元`，与《费用估算》逐格一致（偏差 < 0.1%）。
每次发版以 `python scripts/generate_xlsx.py --verify` 回归。

> 重用系数必须用精确值 1/3、2/3，不能用 0.33/0.67 近似。

### 5.2 NESMA 与国标造价（`scripts/gb_engine.py`）

```python
NESMA_PRE = {"ILF": 35, "EIF": 15}                            # 预估法（GB/T 42588-2023）
NESMA_EST = {"ILF": 7, "EIF": 5, "EI": 4, "EO": 5, "EQ": 4}   # 估算法（NESMA 2.1）
CF = {"预算": 1.70, "立项": 1.45, "招标": 1.25, "需求": 1.10, "设计": 1.00}
# S = UFP × GSC × CF
# AE = PDR × S × SWF × RDF            （PDR 基准 6.96 人时/FP）
# 费用 = AE / 174 × 费率 + 直接非人力成本（DNHC）
```

- `SWF`（业务领域 × 应用类型）、`RDF`（开发语言 × 团队背景）矩阵以 CSBMK-2023 公开口径为种子，全部可配置覆盖
- 基准数据外置 `data/rates_versions.json`，按年度版本（CSBMK-2023/2024）增删改查，`/api/rates` 读写；估算时选用并记录版本
- 因子下拉显示取值与出处；自定义覆盖后在报告与界面标注「人工调整」；非法数值 400 拒绝
- 国标造价管线与 IFPUG 母版的 `SCALE_CHANGE` 口径相互隔离，互不改写

### 5.3 PERT 三点估算

`预期 = (O + 4M + P) ÷ 6`，`标准差 = (P − O) ÷ 6`，并折算理想人月与实际预估人月；项目与估算项长期保存于 `pert.db`。

## 六、接口与前端

- 全部接口挂在 `/api/*`（hand-rolled router），清单见 README「主要接口」
- 前端源码 `frontend/src/`（`index.src.html` + `js/*` + `css/*`），由 `scripts/build_frontend.py` 拼接为单文件 `frontend/index.html`（入库）；改源码后必须重新构建
- 页面：IFPUG 估算（上传/复核/结果）、快速估算、PERT 估算、配置中心、帮助文档
- 界面中/英双语、浅色/深色/高对比三套主题；**交付物文案恒为中文**（见 `docs/设计-多语言边界-交付物恒为中文.md`）

## 七、质量基线

- 单测：复杂度矩阵边界、链路与母版公式偏差 < 0.1%
- 金标准：样本项目 UFP = 234 / US = 105.07
- 识别评价：样本需求类别查全/查准 ≥ 80% 后进入人工确认
- 回归：`npm test` 12 套件（S1–S12）全绿为交付线，详见 `docs/设计-数据与运维.md`
